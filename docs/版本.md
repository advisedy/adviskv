## v0.1.0

### 内容
- 支持副本变更，坏副本替换
- 对于leader分区回来后对于新leader的干扰，实现了pre-vote，不会挤下去了
- 对于失败的写操作，SDK侧支持重试+request_id，失败比例下降，[click here](v0.1.0/retry.md)
- leader崩溃后故障切主的场景，给业务方返回的失败比例下降，[click here](v0.1.0/retry.md)
- 持久化与恢复：KV 当前使用内存 Map 作为状态机存储，但 KV 数据、Raft 状态和 request record 会写入 WAL，并纳入 Snapshot；Storage 重启时从 Snapshot 和后续 WAL 恢复到内存。
- v0.1.0 的 benchmark 跑分记录，[click here](v0.1.0/benchmark/README.md)

### 后续
- request_id 以后打算做TTL，暂时想的是保留30min
- 当前 KV 状态仍以 Map 保存在内存中，后续考虑接入更成熟的持久化存储引擎，减少对整份状态恢复到内存的依赖
- 坏副本替换，当新加入的副本成voter之后，如果坏的副本好了，会把新副本踢掉，考虑优化
- 支持分片分裂操作
- Topo 和 Catalog 目前还只是单进程，后续要考虑高可用
